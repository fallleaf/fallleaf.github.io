从联通云API文档，看"算力一张网"的落地现状

2026年8月，中国联通在中期业绩报告中系统阐述了"六张网"战略布局，明确将新一代通信网与算力网作为核心抓手，提出构建面向Token高效供给的AI算力分发网络（AIDN）。联通云官网的AI服务API文档，则从另一个维度勾勒出这一宏大战略在落地过程中的真实轮廓。

2026-08-27
阅读时长: 7 分钟

导语： 2026年8月，中国联通在中期业绩报告中系统阐述了"六张网"战略布局，明确将新一代通信网与算力网作为核心抓手，提出构建面向Token高效供给的AI算力分发网络（AIDN），实现算力资源的灵活调度与广域分发（见 落实“六张网”部署：中国联通统筹建设新一代通信网和算力网） 。与此同时，联通云官网的AI服务API文档，则从另一个侧面勾勒出这一宏大战略在落地过程中的真实轮廓。

战略蓝图：算网一体的宏大叙事

在2026年半年度业绩报告中，联通交出了一份可圈可点的答卷：上半年营收2014亿元，经营现金净流入333亿元创近年同期新高。其中，算力领域投资占比达37%，同比增长超80%，成为资源倾斜的核心方向。

更值得关注的是战略层面的清晰表述。联通明确将"算力网"和"新一代通信网"定位为"六张网"的两大核心支柱，并提出 AIDN（AI算力分发网络） 作为算网一体战略的核心抓手——依托全国性光网络与骨干传输资源，实现算力资源的灵活调度与广域分发，把算力转化为可度量、可交易、可按需获取的标准化数字服务。

在组织层面，联通同步推进机构改革，管理部门数量缩减近四成，坚持"一个中国联通"，为算力战略落地释放组织活力。

战略方向清晰，资源投入坚决，组织保障到位。这是联通对外传递的强烈信号。

落地现状：API文档中的"碎片化"拼图

然而，当开发者打开联通云官网的AI服务API文档时，看到的画面与战略表述之间存在着一段值得关注的落差。

首先，API域名按物理节点割裂。 开发者面对的不是统一的API网关，而是五个分散的入口：

云区域域名
呼和浩特基地二区https://aigw-nmhhht.cucloud.cn
武汉四区https://aigw-hbwh4.cucloud.cn:8443
济南五区https://aigw-jnzs5.cucloud.cn:8443
贵阳基地二区https://aigw-gzgy2.cucloud.cn:8443
上海二十二区需联系客户经理获取

理想中的"一个联通"AI服务，应当对外提供统一的API入口，后台的"算网大脑"自动完成跨域的资源感知和负载均衡。但当前的产品形态，仍以算力节点为中心，而非以用户服务为中心。

其次，算力资源与模型分布严重不均。 各区域支持的模型数量差异显著：

云区域模型数量覆盖范围
贵阳基地二区27个DeepSeek全系、GLM全系、Qwen全系、Kimi全系、MiniMax、向量及视觉模型
呼和浩特二区7个DeepSeek-R1/V3、蒸馏模型、向量模型
武汉四区8个DeepSeek-V3、glm-5、Qwen-235B、kimi-k2.5、MiniMax
上海二十二区4个DeepSeek-R1/V3、Qwen-397B/235B
济南五区5个DeepSeek-V3.2/V3.1/V3、MiniMax

贵阳基地二区承载了27个模型，几乎覆盖所有品类；而其他四个区域合计仅24个模型，且23个模型仅在一个区域单点部署。这种格局意味着，即便统一网关建成上线，算力调度算法的腾挪空间也十分有限——大部分请求只能路由到贵阳，跨域容灾和负载均衡的能力受到极大制约。

建设与运营：跨专业协同的现实挑战

上述现状可以拆解为两个层面的现实问题：

建设层面：算力资源分布不均衡。 贵阳二区集中了绝大部分模型能力，其他区域相对薄弱。这种格局有其客观现实背景——IDC布局的历史积累、电力与土地成本差异、扩容便利性等因素，决定了资源不可能绝对均匀分布。但对于"算力一张网"而言，资源分布的严重不均直接制约了跨域调度的有效性。AIDN要实现"算力资源的灵活调度与广域分发"，前提是各区域必须具备可调度的资源冗余。

运营层面：API服务入口与软件能力待统一。 五个域名、部分区域甚至需联系客户经理获取接入方式，意味着开发者必须理解底层资源分布才能完成调用。统一API网关的建设不仅是网络连通问题，更是涉及跨域计费、利益结算、系统调度以及软件工程能力的系统性难题。重资产投资能迅速堆砌出算力规模，但统一网关与智能路由等"软能力"的打磨，往往滞后于硬件建设一步。当前的多域名状态，正是这一过渡期的阶段性呈现。

AISN框架审视：从经营资源到经营能力

跳出联通个案，可以从《
从 OpenRouter 到运营商 AI 服务网络系列二：运营商如何从"卖 Token"走向"卖 AI 价值"？ 》建议的运营商在AI时代的服务演进的四层框架—— AISN（AI Service Network，AI服务网络）以及核心原则来审视联通当前的AI服务现状 。

AISN将运营商的AI服务能力划分为四个递进层次：

层次经营对象用户感知
L1 Token经营计量计费，按Token售卖感知算力节点和区域
L2 AI能力经营标准化AI能力调用不关心底层算力在哪
L3 AI任务经营端到端任务完成只提需求，不关心模型组合
L4 AI价值经营业务结果交付只为最终效果买单

该框架的核心原则是：后台经营资源，前台经营能力；后台调度算力与网络，前台交付任务与结果。

可以有以下的结论：

当前处于典型的L1阶段。 API域名按节点割裂、开发者需手动选择区域——这些现象的本质是：底层算力资源的分布细节被直接暴露给了前端用户。开发者需要理解"呼和浩特二区有什么模型、武汉四区有什么模型"，而不是简单调用一个AI能力。这正是AISN框架所反对的——后台的资源调度逻辑，不应成为前台用户的负担。

AIDN的目标是迈向L2。 联通提出的AIDN，其战略意图正是在底层物理算力节点和前端开发者之间搭建一个智能中间层，屏蔽异构算力与物理位置的差异，让开发者面对统一入口、自动路由的标准化服务。这与AISN框架中L2"AI能力经营"的理念高度吻合。

但从L1到L2的跨越，联通面临两个现实约束： 一是资源分布的均衡性——当前贵阳二区承载了28个模型，其他区域合计仅19个，单点部署多，调度算法腾挪空间有限；二是服务入口的统一性——五个域名尚未收敛，软能力建设仍需补课。这两个约束，是AIDN在联通自有资源范围内首先需要解决的问题。

联通显然已意识到这些问题。算力投资同比增长80%以上，AIDN建设推进中，机构改革也在为软件能力提升扫清组织障碍。从战略表态到资源投入，方向是明确的。

结语：从战略到落地，仍有鸿沟待越

联通拥有115万架标准机架、45EFLOPS智算规模、400G骨干传输双平面——这些重资产底牌是竞争对手难以复制的优势。AIDN的战略蓝图也指向了正确的方向。但战略的正确性，最终必须通过产品和服务来验证。

对于开发者而言，“算力一张网"不是一句口号，而是打开API文档时看到的是统一入口还是五个域名；是调用一个模型需要手动选区域，还是系统自动路由；是资源紧张时自动调度，还是开发者手动改代码。

联通云官网的API文档，忠实地记录了"算力一张网"战略在2026年这个时间节点的落地状态。它既不是终点，也不是起点，而是战略推进过程中的一个真实截面。按照AISN框架的演进路径，从L1的Token经营迈向L2的AI能力经营，联通需要在资源均衡布局和软件工程能力建设两个方向持续投入。API何时实现真正的统一入口，不仅是开发者的期盼，更将成为验证联通“算网一体化”战略真实进展速度的关键指标，值得后续持续跟踪。随着AIDN的逐步落地，这个截面会不断更新。届时，开发者看到的，将更接近联通在战略蓝图中描绘的那个"一个联通"应有的样子。
